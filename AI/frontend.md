# 前端：架构、设计语言、录入页、复习页

> 速查：`clms.html` 加载 `assets/app/main.js`（ES 模块，无构建）。`shell.js` 建 bus / store / router 并挂载页面；页面在 `features/<x>/`，渲染用 `html```+`morph`，事件用 data-action 委托。纪律由 `tests/check_ui.py` 强制（规则见 `AGENTS.md`）。

## 分层

```
core/     markdown.js（模型回复的轻量 Markdown，先转义再排版）  sse.js（subscribe：EventSource 封装）  stream.js（postStream：带请求体的 SSE，fetch + ReadableStream，复习助手用）
          files.js（readImages：本地图片 → dataURL）  html.js（转义模板、each、cls） dom.js（render / morph，唯一写 innerHTML 处）
          events.js（data-action / data-change / data-input / data-submit 委托） router.js（#/页面?对象；初始查询保留，同页面查询变化重新挂载）
          store.js  bus.js  api.js（request/get/post，永不抛出，返回 {ok,status,data,error}）  format.js
ui/       icons.js（内联线性图标）  feedback.js（toast 顶部居中、confirmDialog）
domain/   genres.js（板块、评分档、题型表缓存）  paper.js + paper.css（原文、答题横线、默写下划线、红笔 / 蓝笔）
          print-layout.js（唯一A4排版、分页与真实答案测量）  object-links.js + workspace.css（历史/审核对象定位与共用布局）
features/ dashboard  entry  library  review  essays  assistant  audit  history  settings
styles/   tokens.css（唯一允许颜色字面量）  base / ui / shell.css  index.css（@layer 顺序与 @import）
```

依赖方向：core → core；ui → ui、core；domain → domain、ui、core；features/x → x、domain、ui、core。页面之间不 import。

`morph()` 按 `data-key` 对齐列表、保留聚焦输入框的值与选区，所以页面可以放心「状态一变就整页重画」。

### bus 事件

| 事件 | 载荷 | 发出方 → 监听方 |
| --- | --- | --- |
| `page:change` | `{id, prev}` | shell |
| `badge` | `{id, text}` | 录入页（待校对草稿数）、main.js（到期题数）→ shell 导航角标 |
| `library:changed` | — | 录入入库、复习评分、审核/助手执行 → 需要刷新的页面 |
| `context` | `{item_id?,session_id?,prompt_id?,attempt_id?,version_id?}` | 领域页 → shell/store.assistantContext；进入助手保留前页编号，进入其它页先清除旧对象 |
| `audit:changed` | — | 审核执行/修订 → 审核页刷新与角标 |
| `theme:changed` / `nav:changed` | — | 设置页 → shell同步按钮 |

## 设计语言：「答题卡」

- 纸面 `--paper`、原文和题干用衬线 `--font-read`（首行缩进 `--indent`、行距 1.9）。
- 当前正文样式使用系统字体；仓库还保留 `assets/vendor/` 中的字体资源，但没有在这些 token 中强制加载。`tokens.css` 按平台挑系统里最好的：界面 `--font-sans` 西文 / 数字用 Segoe UI（Windows）/ SF（Mac），汉字用苹方、鸿蒙黑体、微软雅黑 UI、思源黑体；代码 `--font-mono` 优先 JetBrains Mono / Cascadia / SF Mono / Consolas，不会落到 Courier。装了 Inter 或 JetBrains Mono 的机器会自动用上。
- **红笔 `--mark` 只用于参考答案**（老师的批改红），错误提示用 `--danger`；学生作答用蓝笔 `--pen`。
- 答题横线 `--rule`（稿纸绿），行距 `--rule-gap` ≈ 答题卡 9mm；默写空是下划线。
- AI 刚改过的字段带 `data-flash`，`--flash` 底色淡出（`--dur-flash`）。
- 四个板块各有识别色 `--genre-*`，只用于小圆点和细边。
- 浅色是纸白 + 墨蓝 `--accent`；深色沿用 OMRS 的暖石墨。主题存在 `localStorage['clms-theme']`。
- 断点（视口）：≤ 1500 录入记录变抽屉；≤ 1160 录入页改为单栏，用「对话 / 草稿」分段按钮切换，复习页左栏变抽屉、复习助手变浮动面板；≤ 760 侧栏变顶栏、控件加高到 40px 便于触屏。唯一的例外：复习评分台内部按题目区自身宽度用容器查询（见「复习页」）。
- 主导航可收成只有图标的窄栏（`--rail-width`，`html[data-nav="mini"]`，存在 `localStorage['clms-nav']`）。
- 滚动条全局细条、跟随主题（`--scroll-thumb`）。
- 动效只用 `--dur-*` / `--ease-*`（系统「减少动态效果」时全部为 0）：新块入场、展开箭头旋转、展开内容淡入、进行中文字流光（`.shimmer`）；大界面切换用 View Transition（`base.css` 里 `::view-transition-*`）。

## 录入页（`features/entry/`）

流程：**居中输入框**（新录入；上传后在这里确认页序 / 方向 / 每页说明，写的话就是补充说明）→ 开始 → **Agent 实时执行**（对话里的时间线）→ 纸面校对 → 入库 →「录下一份」回到居中输入框；左侧是**录入记录**（宽屏可收起）。

| 文件 | 职责 |
| --- | --- |
| `index.js` | 控制器：状态、录入记录刷新、SSE 订阅与事件应用、View Transition（`transition()`）、打开 / 回到开始（`open()` / `fresh()`）、自动保存、编辑 / 发送 / 停止 / 入库等动作、每秒计时 |
| `environment.js` | 设备/视口帮助函数与实际设备资源清理，从控制器拆出保证行数门禁 |
| `listeners.js` | 文档级监听：粘贴截图、拖放（外部文件 / 页面排序）、Enter 发送 |
| `manage.js` | 「管理」动作：录入记录（分组、搜索、加载更多、重命名、回收站、恢复、彻底删除）、准备阶段（页序、旋转、删页、加页、说明、补充说明、开始）、时间线块展开；页面的保存（`savePages`）排队按顺序发、只认最后一次的回复，晚到的旧回复不会冲掉新改动 |
| `layout.js` | 整体布局：录入记录 \| 主区（开始界面，或对话 + 草稿或原图 + 底栏；入库后底栏有「录下一份」） |
| `launch.js` + `launch.css` | 开始界面：标题、居中大输入框（`#composer`）、页面条（等宽等高的缩略图与加页卡片、统一的说明行；图片按顶部对齐并完整显示，悬浮出现 ← / 旋转 / 删除 / → 按钮，可拖动，每页一句说明）、「合成一份 / 每页一份」、快捷问题；没草稿时发送 = 建一段对话并发第一句 |
| `history.js` + `history.css` | 录入记录：按日期分段，缩略图、标题、状态点、时间、页数 / 题数、最近一句话；行内重命名、丢弃 / 恢复 / 彻底删除；宽 > 1500 可收起（`data-collapsed`，内容定宽、收起时 `inert`，状态存在 `localStorage['clms-hist']`），否则是抽屉 |
| `chat.js` | 对话栏：状态条（标题、状态、执行计时、停止、记录开关）、时间线、等待模型时的尾行（流光字）、输入框（快捷指令、附原图、附图、插话、用量圆环）；旧流程的 activity 步骤卡 |
| `gauge.js` | 用量圆环：上下文占用（`stats.context / stats.window`，≥ 70% 黄、≥ 90% 红）；悬浮或聚焦弹出速度（执行中是前端按逐字事件算的实时值）、首字延迟、主 / 子代理轮数、工具次数、累计 token，估算时注明 |
| `timeline.js` + `timeline.css` | 时间线：思考块（进行中展开、逐字；结束收成一行预览）、正文（Markdown，逐字 + 光标）、工具调用行（点开看参数与结果；生成参数时实时显示）、delegate 的子代理卡片（点开是子代理自己的时间线）、执行收尾、手改记录与入库提示；打开后新到的块带 `is-enter` 入场 |
| `canvas.js` / `canvas-items.js` / `edit.js` / `qtype.js` | 草稿画布、纯数据编辑与用户显式新增题型；原图视图按准备阶段的页序与旋转显示。材料的标题 / 作者 / 出处是会自动换行的单行文本框（`data-oneline`：回车不换行、粘贴的换行变空格），标题独占一行，作者和出处另起一行；支持 `field-sizing` 的浏览器按内容定宽。阅读题型下拉只显示「未分类」、当前板块已有题型和「新增题型」，保存新名称后自动选中并保存草稿 |

状态要点（`index.js` 的 `s`）：

- `drafts / counts / total / view / q / limit` 录入记录；`activeId / draft / working / dirty / saving`；`open`（块 id → 是否展开）；`known`（打开时已有的块 id，不播入场动效；从开始界面过来时为空）；`liveSeq`；`liveTps`；`histOpen`（抽屉）/ `histCollapsed`（宽屏收起）；`heroText`（开始界面输入框）；`split`；`starting`；`renaming`；`dragPage`。
- 过渡：开始界面 ↔ 对话用 `document.startViewTransition`，两边的输入框框体同名 `view-transition-name: composer`，所以输入框从中间平滑落到底部（反之亦然），其余交叉淡入；不支持或「减少动态效果」时直接切换。
- 实时：打开草稿即 `subscribe('/api/draft/events?id=&since=live_seq')`（`core/sse.js`）。`delta` 追加到对应块的字段（同时计入实时速度），`block` 整块替换 / 追加，`stats` 更新圆环，都用 requestAnimationFrame 合批重画；`status` / `reload` 250ms 后重新拉草稿和录入记录。`seq ≤ liveSeq` 的事件忽略。
- 滚动跟随：重画前若时间线停在底部（80px 内），重画后滚到底；用户往上翻时不动。
- 补充说明在输入框失焦时保存；「开始」先等这次保存落地再发，避免两者赛跑。
- 准备输入框底部的「加图」「合成一份 / 每页一份」「丢弃」使用相同外框高度；手机上换行时仍保持同一行内垂直居中。
- 请求顺序：`open()` 用 `openSeq`，最后一次打开为准；后台 `loadActive()` 用 `loadSeq`，回来时若 `activeId` 变了、有更晚的刷新、或期间开始过一次打开，就丢弃。`transition()` 先同步改状态，只把重画交给 View Transition，所以过渡期间到达的旧回复同样会被丢弃。
- 录入记录每 4 秒（有执行中的）或 15 秒刷新；执行中每秒重画一次计时和速度。
- 窄屏（≤ 1160）打开草稿默认在「对话」分段。
- 手改、入库、`flash` 等其余行为同前；发送后手动清空 textarea（morph 会保留聚焦输入框的值）。
- 命名注意：`.hero` 是概览页的、`.meter` 是全局进度条，录入页分别用 `.launch`、`.gauge`。

## 复习页（`features/review/`）

工作台页（`workbench: true`：占满高度、各栏自己滚动，页头在页面里）。左栏 + 主区，安排 / 打印预览 / 评分三种状态：

- **安排**（`planner.js` 渲染、`plan.js` 数据与动作）
  - 左栏「复习记录」（`rail.js sessionsRail`）：进行中在上、已评完在下；每行是标题、题数与板块、进度条与「评了 x/y」，悬浮出现打印 / 删除；顶上「安排新的复习」。
  - 页头：到期基准日（下个复习日）、合计「N 题 · 约 x / y 分钟」和「确认安排 N 题」，不用滚到底。
  - 「本次安排」卡片：时间预算、板块芯片、题型下拉、提前复习开关分行排，任一变化即重新推荐（`seq` 丢弃过期回复）。推荐清单按材料分组（左边细边是板块色），每题一个理由芯片（配色按 `tag`）；可移除单题（进 `exclude`，别的题补位）、「全部放回」「换一批」；自选题带「自选」芯片，移除即取消自选。条件下没有题时给出空状态。
  - 「从题库挑题」卡片：`/api/items` 分页，按板块 / 状态 / 添加时间 / 最近练习 / 上次评分 / 关键词 / 排序筛选，「加入」即自选。
  - ≥ 1501 两张卡片并排、控件常显、清单各自滚动；更窄时上下排、整个主区一起滚动。
- **打印预览**（`preview.js`、`preview-actions.js`、`preview.css`）：创建成功默认打开；左栏逐题调默认留白，当前/全部自动适配均由显式按钮触发。主区是同源 `/print/session` iframe，加载自有转义模板与 `domain/print-layout.js`；等字体就绪，以实际答题宽度/字体/字号/行高/换行渲染隐形答案，取高度换算行数。分页、分割长材料/长答题区与独立打印页共用同一脚本/CSS。−/输入/+立即刷新分页，450ms防抖批量回写默认值；新Session沿用。打印/开始复习前刷新保存，失败保留重试，不因打开预览写学习提交。页面卸载后保存可完成，但不再绘制。深链接 `#/review?session=S-…&preview=1` 直接预览，手机可缩放阅读A4并打开留白抽屉。
- **评分**（`grading.js` 渲染、`grading-actions.js` 动作；`focus.js` 是两边共用的「正在看哪道」）：一次看一道题。
  - 左栏「答题卡」（`rail.js questionNav`）：按材料分组的题号，方框里是卷上题序。评过的按评分着色并写出评分，对过答案还没评的方框是红笔虚线，正在看的填墨蓝（`aria-current="step"`）。默写只显示挖空前后几个字（「感时花溅泪，____。」），同一句拆出的几空分得清。底部是快捷键说明。
  - 页头：返回「全部复习」、这次复习、进度、打印 / 含答案（≤ 1160 另有左栏和「助手」按钮）。
  - 这道题（`.rv-q`）：衬线大字题号 + 板块 · 题型 · 分值 · 原卷题号 · 篇名；题干 →「对答案」（空格）→ 参考答案（红笔）与解析 → 自评（评分档和说明常显，数字键直接评；评后显示下次复习日期和「撤销评分」）→ 反馈（回车 / 失焦保存；还没评分时暂存在 `s.pendingNotes`，评分时一起写入）→ 上一题 / 下一题（最后一题给出「去第 n 题（还没评）」）。**改评分时带上已有反馈**：后端改评 = 作废旧记录 + 新记录，不带就丢了。
  - 原文（`.rv-mat`）：篇名、作者 / 出处、原文。原文没有自带 ①②③ 时加段号，段号与复习助手 `material_read` 的一致；每段有 `data-para`（`domain/paper.js`）。同一材料的题前后切换时原文的滚动位置保留。
  - **布局用容器查询**（`grading.css`）：题目区 `.rv-stage` ≥ 920px 且有原文时，原文在左、题目在右，各自滚动；否则题目在上、原文在下，一起滚动（默写这类没有原文的题居中）。这是「视口断点只有 760 / 1160 / 1500」的唯一例外：题目区的可用宽度随左栏、助手、侧栏收起而变，按视口判断会在 1600 左右把两列各挤到 350px。自评四档也按题目卡片宽度排（≤ 400px 时 2×2）。
  - 键盘（`bindKeys`，焦点不在输入框里时生效）：← → 换题、空格对答案（焦点在按钮上时不抢）、0–3 自评（默写 0 / 1 / 3）、/ 打开助手并聚焦输入框。对答案后焦点放在题目卡片上，不放在评分按钮上，否则再按一次空格会误评「不会」。
  - 引用（`quote.js`）：在原文或题目里选中文字（监听 `selectionchange`，停 180ms 后更新），选区末尾浮出「引用」，点了放进助手输入框上方，带位置（《篇名》第 n 段 / 第 n 题题干 / 参考答案）。按下按钮时阻止默认行为，选区不会先收起；滚动题目区时按钮消失。
  - 离开复习页再回来，回到上次打开的复习和那道题（模块级 `memory`，刷新清空）。概览 / 题库经 `store.reviewIntent` 带意图进入时以意图为准。
- **复习助手**（`assistant.js` 渲染、`assistant-actions.js` 动作）：评分台最右一整栏；≤ 1160 是右下角浮动面板（页头「助手」或 `/` 打开），≤ 760 是底部面板。
  - 跟着正在看的题，一题一段对话（模块级 Map，按「复习 + 题」；切页面不丢、刷新清空）。
  - 一条回答按块画：**思考**（进行中展开、逐字；结束收成一行「思考 · n 秒 · 摘要」，点开看全文）、**查阅**（工具调用，写成「看第 3 题」「读《老街的灯》第 2-3 段」；转圈 → 勾 / 叉，点开看查到的内容）、**正文**（Markdown，「【建议】」之后的内容流式期间隐藏）、**建议卡片**（左边竖线按评分着色；「采用评分和反馈」→ `/api/session/grade`；「只填反馈」→ 已评分走 `/api/record/update`，未评分暂存）、**用量**（查阅次数 · 秒 · token）。
  - 快捷「打分」「写反馈」「怎么答」「差在哪」；回车发送、Shift+回车换行、可附 / 粘贴作答照片；可停止，出错可重试。
  - 发给后端的历史只有每轮的文字和「查阅过什么」的标签，不带查到的内容（需要时模型会再查，见 `ai.md`「复习助手」）。
- ≤ 1160 左栏变抽屉（页头左边的按钮，带遮罩）；≤ 760 页头压成两行（左栏按钮 · 标题 · 助手 ／ 返回 · 进度 · 打印），按钮只留图标。
- 旧的「拍照交给 AI 批改」入口 0.5 起移除（后端 review 会话保留，见 `ai.md`）。

## 作文页（`features/essays/`）

一级「作文」页面提供完整流程：**作文题列表/搜索 → 题目详情与自由分类 → 新建一次练习 → 多页上传一版 → OCR → 原图对照校对 → 确认正式转写 → 查看/保存评价 → 记录讨论重点 → 上传下一稿**。它独立于普通题库和复习工作台，不显示记忆曲线或普通复习评分。

| 文件 | 职责 |
| --- | --- |
| `index.js` | 页面状态、领域查询、列表/详情请求序号、OCR 轮询、轻量页面上下文、卸载保护 |
| `actions.js` | 委托动作：创建题/练习、添加分类、读图/排页/上传、OCR、校对/确认、评价/采用、笔记、版本对比 |
| `view.js` | 作文题列表、题目与练习详情、上传准备、版本导航、讨论笔记与差异对比 |
| `version.js` | 当前稿状态、原图翻页、校对与正式正文、原始 OCR、存疑处、评价列表与追加表单 |
| `shared.js` | 时间、深链接、禁用属性和来源名称的共享展示函数 |
| `essays.css` | 双栏题目/详情、原图/文本对照、稿件进度、评价与文本差异，以及手机单栏布局 |

题目列表按名称、正文、要求、来源和自由分类搜索，也可选分类过滤。题目详情显示完整题目/要求、出处、分类、练习数量与每次练习的版本数。练习页显示版本总数与 **修改次数 = 版本数 - 1**，版本卡注明时间和评价数量；题目/要求可以在练习中展开查看。`#/essays?prompt=EP-…`、`?attempt=EA-…`、`?version=EV-…` 均可刷新和直接打开，历史中的旧评价链接会打开对应旧版本。

上传选择图片后先显示页序、页名和缩略图，可前移、后移或移除。逐页上传使用已有 `/api/image`，最后一次 `/api/essay/version` 把所有图片引用作为一个版本提交；OCR 必须由「开始原样转写」显式触发。转写期间轮询当前练习，每次只接受最近详情请求；失败在原版本显示错误和「重试」。原图以多页翻页方式对照完整校对文本，点击可看原始尺寸，存疑处单独展开，原始 OCR 文本也可查看。

校对输入保存在当前页面的 `textDraft`，显示是否未保存。「保存校对」提交当前整数 revision；「确认正式转写」提交当前全文并明确进入正式确认状态。通过页面内导航切题/切稿前，先保存未保存的校对，失败则保留当前页面；离开全局导航前请显式保存校对。已确认正文以只读纸面显示，后续修改只能上传下一稿。校对输入和确认都不增加版本/修改次数。

每份评价展示分数 `/60`、摘要、优点、问题、建议、评价者/模型、来源和时间，可以选择当前采用评价；其它评价始终保留。可自行追加评价，或经「与 AI 讨论这篇作文」进入 `#/assistant?version=…&attempt=…&prompt=…`，只带对象 ID。页面经 `bus.emit('context', …)` 发布 `prompt_id`、`attempt_id`、`version_id`，正文不会当作系统指令。讨论笔记默认关联当前版本，也可归属整次练习；新稿不会覆盖旧笔记和评价。

当前稿和前一个已确认稿可以直接比较。普通正文逐字展示新增/删除，超长正文按段落比较以限制计算量；左右旧/新文本都完整保留。自由分类可以在题目、练习、版本三个层级分别追加，没有必选分类树。

桌面是左侧题目列表、右侧练习/稿件详情，宽度 ≤1160 时原图和文本上下排列。≤760 时全部单列，打开详情后题目列表默认收起，通过「作文题」按钮展开；表单控件保持触屏高度，文字输入不低于 16px。操作使用原生链接、按钮、表单和有标签的控件，保留键盘焦点。页面卸载立即注销委托动作、清除轮询/搜索定时器，并令所有未完成查询与写请求失效；晚到回包不得重新绘制。

专项 `tests/e2e_essays.py` 启动真实 CLMS 和本机 OpenAI 兼容伪 OCR HTTP 服务，以三张模拟稿纸原图验证失败重试、原图翻页、校对、确认、来源评价/采用、下一稿绑定、差异、390px 搜索与键盘、深链接刷新和卸载后的延迟响应。它验证浏览器与真实本机传输，不验证真实模型的识别准确率或真实手机硬件。

## 其它页面

- **概览 `dashboard/`**（`dash.*`）：今天是否复习日、下一批的日期与题数、两周日历（复习日画圈）、四个板块卡片、题型薄弱榜、未完成的复习与最近动态。「排这次复习」经 `store.reviewIntent` 带意图跳到复习页（`{plan}` / `{session}`；题库还会带 `{pinned}`）。
- **题库 `library/`**（`lib.*`）：两个分页。未分类作为正式题型分面显示，值为 `__unclassified__`；列表与详情显示「未分类」，可进入编辑选择已有题型。
  - 「题目」：左侧分面筛选（`view.js facets`：状态含顽固 / 已停用 / 已删除、记忆类型、添加时间、最近练习、上次评分、题型；每项显示按其它筛选算出的题数，再点一次取消；≤ 1500 收进工具条的「筛选」按钮）；工具条（板块分段、搜索、按题 / 按篇、排序、批量选择）；列表每页 50 题 / 20 篇，「加载更多」。按题的行显示板块 · 题号 · 题型 · 篇名 · 出处（会换行，不截断）、两行题干、上次评分 / 录入时间 / 出错次数，右侧状态、掌握度条、到期（理解型掌握后不再安排时显示「不再安排」）。按篇时每篇（默写按出处）一张卡片：篇名、作者、题数、已掌握 / 新 / 顽固、平均掌握度，下面是其中的题。批量模式：点行勾选、「选这一篇」「全选已加载的」，底部批量条「加入复习 / 停用 / 恢复复习 / 删除」（`/api/items/batch`）。
  - 「复习记录」（`history.js`）：全库复习历史，按板块 / 评分 / 时间 / 只看写了反馈的 / 显示已撤销的筛选，分页；点一条在右侧打开这道题。
  - 右侧详情（`detail.js`）：状态卡（状态、记忆类型、掌握度、下次、上次评分、出错）、纸面题目与红笔答案（篇名 / 作者 / 出处换行显示）、同一篇的其它题（点击切换）、复习记录（补记、改评、反馈、撤销、恢复）、「加入复习」「编辑」「停用」「删除」；已删除的题可「恢复到题库」。
  - 「加入复习」（单题或批量）经 `store.reviewIntent = {pinned: [题号]}` 跳到复习页，成为自选题。筛选、分页方式、列表方式存在模块级 `saved`，切页面回来不丢。
- **复习 `review/`**（`rv.*`）：见上面「复习页」。
- **设置 `settings/`**（`set.*`）：`index.js`管状态/保存/生命周期，`view.js`管七区布局，`sections.js`管原AI/复习/数据表单，`mcp.js`管Key展示与委托动作，题型控件在`taxonomy.js`。外观与显示、复习与打印、AI识别、AI助手、外部AI/MCP、数据与存储、服务与运行分区；最后选择存在localStorage。桌面左侧区导航，≤760水平可滚动页签；Arrow/Home/End切页签并聚焦，aria-selected/tabpanel有真实字符串值。AI识别保留模型、超时、输出 token 上限、并发数、Agent 模式开关、子代理并发、每次最多轮数；「题型体系」按现代文 / 文言文 / 古诗展示当前题型数、未分类题数及各题使用数，可新增、重命名、删除（使用中显式选择迁移目标）、上下移动排序、切换理解型 / 记忆型，移动端同样可操作；复习日（七个按钮）与默认时长、校验提交链、导出脱敏源代码（链接下载 `/api/source/export`）。题型变更更新 `domain/genres.js` 的缓存，下一页面读取立即看到新体系。


设置页「服务与运行」展示当前版本、Web 和实际 `mcp.url`。`service.js` 提供重启卡片及委托动作：确认框说明正在进行的 AI 会中断、应先保存编辑；按钮提交当前 `instance_id`，等待期间禁用重复点击。每秒查询 `/api/status`（单次请求最多2秒、总等待45秒），仅在不同实例上线且未重启中时自动刷新；刷新后仍停在原设置分区，并提示「程序已重启」。请求断网或超时可能已经被接受，因此不自动再次 POST。等待超时显示「检查运行状态」「刷新页面」，检查继续等待原实例的替换。接口明确拒绝时显示服务端原因；嵌入式服务不支持重启，按钮禁用并说明启动方式。页面卸载中止请求、清理定时器，晚到回包不刷新其它页面；读取到旧实例正在重启时自动继续等待。重启不会保存浏览器里尚未提交的字段。

## 全局助手（`features/assistant/`）

一级工作台：对话列表、消息/思考/工具时间线、审核确认卡、输入框及运行/用量。`index.js` 管会话查询、长轮询、动作、停止与页面上下文；`model.js` 把共享harness事件还原为块；`view.js`用转义模板和安全Markdown；`assistant.css`提供桌面双栏和手机对话抽屉。消息、事件、会话和运行持久化，刷新按cursor续读，不把思考再发给模型。等待审核仍可离页，后台运行持续等待；聊天卡/审核中心使用相同id/revision和人工决定接口，模型没有批准工具。

`#/assistant?conversation=A-…`（兼容`?id=`）打开持久会话；从作文带`prompt/attempt/version`编号新建讨论上下文。页面上下文只选稳定ID，不传正文或系统指令。Enter发送，Shift+Enter换行，Escape关闭手机列表；展开工具可查schema参数/结果。卸载注销动作、取消poll和定时器，generation抑制迟到响应。切会话同样取消旧轮询，只接受当前会话结果。

## 审核中心（`features/audit/`）

一级待审核/历史页。显示来源（内置/录入助手或MCP）、类型、时间、到期、revision、原对象、字段前后表或Session标题/分钟/数量/题单。可修订字段由服务端原请求范围给出；提交revision乐观锁后才批准/拒绝。处理结果显示正式编号与领域链接，详情可展开原请求/修订/决定。自动刷新和加载更多；`#/audit?id=op_…`定位具体操作。请求序号和alive保护确保切tab/卸载后不重画，服务器的审核决定是唯一权威。

## 历史记录（`features/history/`）

「学习与变更」读Ledger，「系统运行」读脱敏runtime，各按日分组。搜索250ms防抖，日期/source/type筛选后分页加载；详情展示真实记录及题目/Session/作文/审核/会话链接。模型学习提交按`_operation.source`显示/过滤来源，仍保存原domain_source。旧评价只跳原Version，分类按target_type定位；MCP提案通过审核id可看到最终Session。tab/详情/列表有请求代数，卸载清定时器，迟到响应无效。

## 手机与生命周期

布局保留760/1160/1500三断点；全屏工作台使用dvh回退，视口允许软键盘resize、安全区padding；coarse pointer输入字号至少16px、触控控件touch-action:manipulation，hover只在支持悬浮设备启用，避免手机粘连。装饰/布局动效沿用token并尊重reduced-motion。390px浏览器验证不能替代实体手机的相机、软键盘和打印系统测试。
