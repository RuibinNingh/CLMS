# 前端职责与行为

## 审核中心可读提案（0.10.1，已发布）

独立分支 `codex/review-center-draft`，工作树 `/root/.codex/worktrees/review-center-draft/clms`。0.10.1 已于2026-10-11 10:11:55（Asia/Shanghai）从固定提交 `969ad07` 发布到生产；原工作区和主分支保留。审核中心先说明实际提交的操作（新建/修改题目、分类等）与通过后的影响；不推断 AI 的思考、工具调用或未提交的文件。客户端模型名称只在来源记录中标为自报信息。

`reviewPresentation.ts` 集中操作、标题、入档影响与页面选择。`ProposalContent.tsx` 将题目/分类/入档/修改稿/反思显示为中文字段与原值/提案对照，评价沿用精确版本的 `EvaluationView`。组合入档逐项展开题目、内联分类与写作/稿件；保留 JSON、原请求、来源、目标 ID 与两个哈希的折叠检查入口。省略的题目更新字段继承冻结原值，显式 null/空列表按提案显示。

题目材料接入鉴权阅读器；只提交文字时明确显示「未附原始材料图」。修改稿主阅读器使用本次提案的 pages，上一稿通过独立折叠阅读器查看，不再因读取 parent_version_id 而优先显示旧稿。窄屏材料/原稿与提案切换使用正确标签。

`PendingReviewBadge.tsx` 使用真实 pending total 显示导航数量气泡，与队列筛选结果数量分开；进入路由、窗口重新获得焦点、页面重新可见、每30秒及人工保存/决定后刷新。后台只刷新数量，不覆盖编辑表单。读数失败隐藏气泡，不编造零。空队列提供查看全部提案入口，已处理提案仍可直接打开详情。

`shared/HelpTip.tsx` 提供流程、有效修订、材料、评分与决定说明，支持精确鼠标悬停、键盘焦点、点击/触摸、Escape 和点击外部关闭；浮层经 portal 定位并限制在视口内，触屏按钮至少44px。颜色与宽度/层级使用 CSS token。浏览器触屏模拟不代表实体设备通过。

桌面长队列独立滚动，选中提案保持在队列视口内；手机进入详情后收起筛选与流程条，返回队列后恢复。审核操作放在正文末尾，避免遮挡内容。

工程验证保存在 `artifacts/review-center-ui/ready/verification.json`、源码/构建哈希证明及 `artifacts/review-center-ui/browser/review-draft-*.png`；工程用独立合成临时库和官方 MCP 客户端真实端口。生产另验20项 HTTP、四种登录布局、数据一致性和冷备份；没有管理员密码，未复测生产登录后的业务。生产摘要 `artifacts/review-center-ui/production-969ad07.json`；工程门禁、外部真实 AI、实体设备及生产发布分别记录在 progress.md。

React + TypeScript + Vite，生产前端同源，所有业务来自真实 `/api`。页路由采用 hash，一级导航只有作文档案、审核中心、分类管理、设置。共享 API 处理错误/会话/CSRF，CSS token 集中颜色、字号、间距和主题。

## 书页档案设计语言（0.10.0）

采用纸白与墨蓝，标题及总体评价用阅读衬线字体，控件用系统无衬线字体。深色主题使用蓝灰底，原稿图像始终保留原色。颜色、字号、间距、圆角、阴影和按压反馈集中在 `app/tokens.css`，hover 仅用于精确指针，减少动态效果时关闭位移。

品牌使用已完成的「墨燕」图标，保留墨绿底、纸白折页及朱红燕喙；不随页面主题重绘或改色。`shared/Brand.tsx` 引用 `public/icons/clms-icon.svg`，用于导航与登录页；`index.html` 引用同源 SVG/ICO favicon 与 Apple touch icon。运行资源从原设计产物精确复制，原 `output/design/clms-icon/` 不作为运行依赖。`shared/Icon.tsx` 提供装饰性操作线图标，动作保留文字或可访问名称。

大屏侧栏显示图标和文字；760–1160px 收为图标栏，名称仍由 aria-label/title 提供；760px 以下显示品牌、四项导航和退出按钮。编辑字段至少 16px，触屏控件至少 44px；动态视口、安全区及随实际主题更新的浏览器主题色用于移动端。浏览器模拟不能证明实体设备的键盘、刘海和触摸手感已通过。

| 模块 | 职责 |
| --- | --- |
| archive | 双列书页卡片、语言分段筛选、搜索/分类/状态/折叠日期筛选、真实分页；题目与独立练习详情、版本/评价历史 |
| submission | 新题/独立练习/修改稿、题目材料与作文原稿分别上传、页排序/移除/旋转、保存到真实 API |
| document-viewer | 页导航、缩放、适宽、原件下载、精确页映射；共享阅读布局负责原稿/评价窄屏切换，比较稿件各自保留页导航 |
| evaluation | 展示总体评价、优点、问题/建议/待确认、可空分数、部分覆盖限制、定位与历史 |
| review-center | 队列/详情、有效提案、目标快照、原图与评价对照、修订保存、通过并入档/驳回、真实回执 |
| categories | 用户自建、名称/scope、改名排序停用；初始无类别 |
| settings | 明暗主题、限额/存储说明、MCP连接与一次展示凭据；无模型/OCR/调度配置 |

路由：`#/archive`、`#/submit`、`#/prompt/{id}`、`#/submit?prompt={id}`、`#/submit?attempt={id}&parent={version_id}`、`#/reviews`、`#/categories`、`#/settings`。

原稿保存后直接入档，不出现 OCR/识别/校对步骤。同题重新写一篇创建新练习，从 V1 开始；上传修改稿创建同一练习 V2，原稿与旧评价继续可看。待审评价不算有效正式评价，最新有效稿只有部分评价时仍待完整评价。

档案列表显示当前页题目档案数量，卡片使用真实语言、分类、评价状态、练习次数和写作日期，不补造总量、分数、版本号或排序说明。日期筛选和其它筛选一样会重置分页游标。

详情 `PromptDetail.tsx` 管理独立练习/稿件选择；`VersionWorkspace.tsx` 管理当前精确版本的阅读、评价、复制任务及对比。题目与要求默认折叠，读取所选练习的冻结快照；编辑题目仍操作当前题目，不覆盖快照。反思与定稿选择放在原稿/评价之后的折叠区。切换主稿件会重置评价、定位与比较选择，作废记录明确标记且保留可查；状态直接使用 API 的 version.status。

`shared/ReadingLayout.tsx` 在宽屏将原稿与评价并排；档案详情 760px 以下、审核详情 1160px 以下用「原稿 / 评价」切换。两个面板保留挂载，切换不会清空本地编辑；点反馈位置会选择对应原稿页、切回原稿并将焦点与滚动位置移到阅读器，留出固定导航高度，重复定位同页仍有效。窄屏复制任务按钮显示图标并保留可访问名称。双稿对比桌面并排，760px 以下选择显示其中一稿，不把两张长原稿叠在一起。每稿的评价仍绑定该版本。

「复制评价任务」仍包含精确的题目/练习/版本 ID、两项哈希及 MCP 阅读/提案要求；剪贴板不可用时显示可手动复制的文本。尚无正式评价时不推断有待审提案；评分可空，不填默认满分。评价突出总体评价、明确问题/优化建议/待确认与原稿定位，长 ID 和来源记录放在折叠信息里。

审核队列保持真实过滤结果 total，切换到另一提案时重新读取队列，避免外部新建提案后仍显示上次空队列；窄屏选中提案后进入详情，用「返回队列」返回。详情在对照原稿/有效提案前显示冻结题目、Vn 和页数，目标 ID/哈希仍可在快照中查阅。`ReviewProposal.tsx` 负责编辑、有效预览与真实回执；阅读面板选择保存在详情层，保存修订后继续显示评价预览，原有脏状态/冲突/无效输入的保存及决定门禁继续生效。

审核与提交表单的本地草稿同步暂存；路由、队列切换和前后退后重新进入可恢复，刷新/关闭由 beforeunload 提醒，不设置额外路由确认框。自动刷新不得覆盖修改，失败保留输入，字段错误可定位。用户文件名和 Markdown 作为安全文本展示，不执行 HTML 脚本。

分类和题目提案会显示缺省的可修订字段，未触碰的字段不加入修订；JSON 空占位不会制造脏状态。已关联正式题目的入档提案不提供新题目和内联分类改写，目标身份、哈希和基线保持只读。

目标视口 1440×900、1280×800、800×1280、390×844、320×740；明暗主题均验证。真实服务/浏览器的 F01–F08 和截图由 `scripts/browser_verify.py` 运行，使用标记为合成的原稿及新临时库；结果进入本次独立的 `artifacts/book-page-ui/`。新增浏览器验证覆盖品牌资源、反馈定位、手机对比切换、主版本切换、冻结题目显示和双列列表。外部模型、实体设备和生产发布单独记录。
